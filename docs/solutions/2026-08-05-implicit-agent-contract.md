# Контракт трёх сервисов контура существовал стихийно и ломался молча

## Ситуация

Три сервиса контура производства — poh-issue-agents, poh-pr-agents, poh-pr-closer —
обменивались работой через GitHub, но контракт между ними нигде не был записан:
соглашение об именах веток `research/issue-<N>` существовало только в коде одного
сервиса, метки расползлись по трём репозиториям, и нигде не было зафиксировано,
кто какую метку пишет и кто её читает. Такой контракт ломается молча: достаточно
переименовать метку в одном сервисе — остальные участники этого не заметят.

## Причина

Контур вырос из трёх независимых сервисов, и соглашения складывались в коде и
спецификациях каждого сервиса отдельно: GitHub использовался как общая среда,
но общего документа-словаря никто не заводил. Почему так вышло — по истории PR
не выяснено.

## Решение

В корень профиля организации добавлен `AGENT-PROTOCOL.md` (+207 строк) — явный
контракт: GitHub описан как «доска объявлений, а не транспорт» (контракт — это
словарь меток, состояние процесса живёт в GitHub, порядок вебхуков не
гарантирован); сквозной ключ трассировки `root-issue` связывает задачу, ветку,
PR, follow-up и атрибуты поиска Temporal; словарь меток построен по правилу
«одна метка — один писатель»; зафиксированы восемь правил контура (дедлайн на
каждую парковку, рубильник `agents:off`, взаимное уважение стоп-меток,
обязательный провенанс) и пять точек передачи с условиями готовности. Отдельно
зафиксирована граница делегирования: агенты работают до кода и после кода, код
пишет человек. `profile/README.md` получил ссылку на документ.

## Как проверить

Открыть `AGENT-PROTOCOL.md` в корне репозитория: словарь меток, правила R1–R8
и точки передачи H1–H5 на месте; из `profile/README.md` ведёт ссылка.
Автоматической проверки нет — документ контрактный, живёт ревью изменений меток
в сервисах контура.

## Уроки

Неявные соглашения между сервисами (имена веток, метки, очереди) надо сводить
в явный словарь, пока они не разошлись: ломаются такие вещи молча, без ошибок
в коде. Правила «одна метка — один писатель» и сквозной ключ трассировки дешевле
ввести заранее, чем переименовывать метки после расползания.
